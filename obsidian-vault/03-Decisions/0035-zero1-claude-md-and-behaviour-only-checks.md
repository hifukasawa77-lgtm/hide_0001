# 0035 — ZERO-1（PC版）に CLAUDE.md を新設し、検査は「振る舞いだけ」を見る

## 背景

2026-09-09〜10 のセッション（ZERO-1 PC版のセキュリティ改善・JARVIS機能6件・realtime配線）で、
**同じ種類の失敗を6回踏んだ**: 検査が実装の置き場所や書き方を照合していて、
実装を良くする（区画を切り出す・lazy にする・提供元の新しい形へ追随する）たびに
**検査だけが赤くなる**。動きは1つも変わっていない。

調べたところ、**そのルールは既に `zero-1-local-ai/docs/開発の注意.md` §6 に書いてあった**
（「検査は `app/page.tsx` を名指しで読まない」）。それでも踏んだ理由は2つ。

1. **書き方が狭すぎた** — `page.tsx` 限定に読めるので、他のファイル名・式・
   提供元の項目名を照合するのは別の話に見えた
2. **そのファイルが自動で読まれない** — `zero-1-local-ai` には `CLAUDE.md` も `.claude/` も無く、
   `docs/開発の注意.md` は思い出した人しか読まない。当のセッションでも
   `/self-improve` を回すまで一度も開かなかった

## 決定

1. **`zero-1-local-ai/CLAUDE.md` を新設する**（64行）。毎回効く決まりだけを写し、
   本体 `docs/開発の注意.md` へ誘導する。Claude Code は CLAUDE.md を自動で読むため、
   次のセッションから確実に効く
2. **検査の原則を一般則へ書き直す** — 「実装の置き場所・書き方を照合しない。見るのは振る舞いだけ」。
   代わりに見るのは、値が合っているか／意味が在るか／繋がっているか。
   `docs/開発の注意.md` §6 と `.claude/agents/verifier.md` 原則#3 の両方へ
3. あわせて `docs/開発の注意.md` に §7「届いている理由を捨てない」・
   §8「外の相手の形は、こちらの都合で変わらない」を新設

## 根拠

- 落ちた検査を直す手間（数分）は本質ではない。**「良くすると赤くなる」体験が改善そのものを止める**。
  `page.tsx` が行数上限に当たったとき、切り出すたびに無関係な検査が落ちるなら、
  次からは切り出さずに詰め込む方へ倒れる
- **想起されない場所にある学びは、無いのと同じ。** 蓄積（書く）と反映（ルール化）が
  揃っていても、自動で読まれる場所に無ければループは閉じない。
  [[0003-recursive-self-improvement-loop]] の想起フェーズが、別リポジトリでは
  成立していなかったことになる

## 影響

- `zero-1-local-ai` で作業する次のセッションから、上記の決まりが自動で効く
- ポートフォリオ側の `verifier` エージェントが、この失敗形を検査設計時に避けるようになる
- **未解決**: `zero-1-local-ai` には SessionStart hook（recall）が無い。Vault も無い。
  CLAUDE.md で当面は足りるが、あちらでの学びは今も手動で持ち帰る必要がある
