## 学んだこと

### 実装を良くすると落ちる検査を、1セッションで6回踏んだ
ファイル名・式・提供元の項目名を照合していた検査が、切り出し／lazy化／GA追随のたびに落ちた。
動きは1つも変わっていない。→ [[checks-that-break-when-code-improves]]
**そのルールは既に `docs/開発の注意.md` に書いてあったのに踏んだ**——書き方が狭すぎたのと、
**そのファイルが自動で読まれない**（`zero-1-local-ai` に CLAUDE.md が無かった）のが理由。
→ [[0035-zero1-claude-md-and-behaviour-only-checks]]（昇格済み）

### 届いている理由を捨てていた
［音声のまま話す］が押した瞬間に灰色へ戻り、画面には「提供元との接続が終わりました。」だけ。
理由は届いていたのに、①error イベントを `lastError` へ**覚えるだけ**で画面へ出さない
②WebSocket の close(code, reason) を形合わせが渡さない、の2か所で捨てていた。
出すようにしたら**次の1回で確定**した:
「The Realtime Beta API is no longer supported.（beta_api_shape_disabled ／ 終了番号 4000）」
→ 「例外もエラーも出ない」より質が悪い。**こちらが消している**ぶん

### 外の相手の形は、こちらの都合で変わらない
beta→GA で `session.update` の形が総入れ替えになっていた。同じことが**使用量の読み取り**でも
起きうる——そして壊れても例外は出ず、**数えられないまま課金が止まらなくなる**。
入れ子の名前を決め打ちせず「方向を含む鍵の中の `audio_tokens`」を探す形にした

### `npm run test:fast` だけで済ませると、予算超過が黙って積み上がる
ビルドを伴う検査だけが見ているものがある。コミット前は必ず `npm run check`
