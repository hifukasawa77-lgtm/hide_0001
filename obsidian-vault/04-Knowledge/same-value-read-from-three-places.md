# 同じ値を3か所が別々に引くと、無言でずれる

## 症状（2026-09-07・PC版 ZERO-1）

画面と稼働ログが食い違った。

```
画面     ZERO-1 Original — qwen2 · 7.6B ／ ● すぐ答えられます
稼働ログ 生成を開始 モデル=gemma4:latest
         最初の1文字 ms=59924
```

利用者からは「速いと書いてあるのに60秒待たされる」としか見えない。
例外もエラーも出ない。**遅いのはモデルのせいだと誤診する**。

## 原因

「いま使うモデル」という**1つの概念**を、3か所が別々に引いていた。

| 用途 | 引いていた値 |
|---|---|
| 画面のラベル | `models.find(...) ?? models[0]` |
| 温める先（先読み） | 同上 `.id` |
| 実際の送信先 | `selectedModel` |

`selectedModel` が一覧に無いと、ラベル側だけが **`?? models[0]` で黙って先頭へ落ちる**。
温めたモデルと送ったモデルが別物になり、温めていない8Bを冷たいまま読み込む＝60秒。

## 学び

- **`?? 既定値` は「描画を止めない」ための道具で、「食い違いを隠す」道具ではない**。
  落ちたことは `matched` のような形で呼び出し側へ返す。返さないと目に見えない
- 同じ概念を2か所以上が引いているなら、**関数1つに畳んで全員がそこを通る**ようにする。
  片方だけ直すと、直したはずの不具合がもう片方から再発する
- **「速い」と表示する側と、実際に速くする側が別の値を見ていないか**を疑う。
  進捗・準備完了・残量のような“状態表示”は、この事故が最も出やすい場所
- 検査は純粋関数だけを叩かない。**画面がその1つの値を実際に使っているか**まで見る
  （`model: selectedModel` が残っていないことを静的に確認する）

## 併発した別件（同じ「無言」の形）

考え中の吹き出しの入れ物に `.message-body`（`min-width:0`）を付け忘れていた。
思考プレビューは `white-space:nowrap` なので、flex の既定 `min-width:auto` で
**入れ物ごと広がり `max-width:100%` が効かない**。画面に横スクロールが出るだけで
例外は出ない。flex の中で省略記号を効かせるには祖先の `min-width:0` が要る。
