# 偽の赤（false red）は、検査が無いより悪い

`verify-game-assets.mjs` は **必須検査**（CLAUDE.md）なのに、実行すると常に赤だった。
中身は2種類とも**検査側の欠陥**で、リポジトリは壊れていなかった。

## 何が起きていたか

1. **静的検査が29件の偽FAIL** — 参照の解決先を「リポジトリ直下 / 参照元のディレクトリ /
   `assets/` / `assets/<直下1階層>`」に限っていた。源平争乱記のアセットは
   `assets/genpei/hex-battles/` という**2階層のルート**で、ページ側は
   `HEX_BATTLE_ROOT + 'backgrounds/01-x.webp'` と実行時に組み立てる。
   → 実ファイルは在るのに全部「実在しない」と報告されていた。
2. **別オリジンの失敗をローカル404と同じ扱いにしていた** — Google Fonts や jsdelivr が
   回線・プロキシで落ちると、リポジトリと無関係にページが赤くなる。
3. **検査自身が起こした遷移の中断を404と呼んでいた** — 検査は画面を触ってアセットを引き出すため
   クリックとEnterを送る。リンクを踏むと遷移が始まり、検査の終了で中断される。
   実在する `poker.html` が `card-games.html` の「404」として報告されていた。

## なぜ放置されると危険か

**赤が常態化した検査は、やがて誰も読まなくなる**。29件の偽FAILの中に本物の1件が混ざっても
気づけない。「検査が無い」なら少なくとも人が目視するが、「常に赤い検査がある」は
**見なくてよい理由**を与えてしまう。偽の緑（素通り）と同じくらい、偽の赤も検査を殺す。

## 直し方の原則

- **解決先を推測で広げない**。広げれば偽の赤は消えるが、代わりに**誤った場所で解決して
  本物の間違いを見逃す**（偽の緑へ裏返る）。採った解は「**そのファイル自身が宣言している
  `assets/.../` という文字列だけ**をそのファイルの解決先に加える」＝根拠のある拡張。
- **環境で落ちるものと、リポジトリで落ちるものを分ける**。別オリジンは `△ 外部` として
  表示だけする（黙って捨てると「CDNが落ちている」ことにも気づけない）。
  これは `dynamic-test-auto.cjs` が先に持っていた設計で、こちらへ横展開しただけ。
- **例外を作るときは「実体で判定する」**。中断（`ERR_ABORTED`）の除外は**ファイルが実在するときだけ**に
  限った。理由コードだけで除外すると、実在しないページへの中断まで消える。
- **直したら故障注入で確かめる**。今回は5パターン（宣言ルート配下の綴り間違い／どこにも無いパス／
  実在しないローカル画像の実読み込み／ページ内例外／実在しないページへのリンク）すべてで ✗ を確認した。

## 教訓

**「必須」と書いた検査が赤いまま放置されていたら、まず検査を疑う。**
実装を直す前に、検査が何を根拠に赤いのかを見る。

## 後日談 — 偽の赤を消したら、本物が2件出た

同じ日に全95ページを通したところ 96 ok / 2ページFAIL。**どちらも偽の赤に埋もれていた本物**だった。

- `hyakki.html`: 実行時に組み立てるパス（`` `assets/hyakki-char-${i}.png` ``）だけWebP移行から
  取り残され、キャラ画像5枚が**例外も出さずに**表示されていなかった。すぐ下の別ブロックは `.webp` で、
  **片方だけ直っていた**
- `notebook.html`: CDNが読めないと `init()` の1行目で ReferenceError になり、**ページ全体が無反応**。
  整形が効かないだけのはずが、資料一覧も保存済み結果も出ない状態だった

**「常に赤い検査」は、赤の中身を見なくする。**29件の偽FAILの陰に、2ページの本物が半年単位で隠れていた。
